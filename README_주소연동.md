# 햇빛소득마을 수익 시뮬레이터 — 주소 연동 버전

원본 SolarPowerGeneration-local(1).zip의 React/Vite 프로젝트를 수정했습니다. 카카오맵 및 별도 지도 라이브러리는 사용하지 않습니다.

## 1. 변경 기능

- 좌측 변수 설정 제목 우측 `주소로 입력` 버튼 → 같은 InputView 내부에 펼쳐지는 패널
- 도로명 또는 지번주소 입력 → 브이월드 지오코더 → 연속지적도 좌표 조회 및 PNU 확인
- 토지 면적: 토지·임야대장 면적 우선, 실패할 경우 연속지적도 폴리곤 계산값(추정)으로 대체
- 건물 면적: 해당 PNU의 GIS건물통합정보 폴리곤 수평투영면적 합계(동일 도형 중복 제외). 실제 옥상 유효면적이 아님
- 자동 맞춤 항공사진 지도. 필지/건물 경계와 주소 위치 마커 표시. 사용자의 지도 조작 없음
- 토지/건물 면적 선택 → 1kW당 필요 면적을 확인·수정 → `변수에 적용`
- 설비 용량, 지역, 일조량, 분류, REC 가중치 및 기존 수익 그래프/PDF 입력 데이터 자동 반영
- 조회된 면적이 기존 50~1,000kW 범위 밖이더라도 실제 환산값을 입력할 수 있도록 슬라이더 범위 확장 및 1kW 단위 변경. 기존 추가대출이 변경된 자기자본을 초과하면 제한
- 검색 결과가 없는 경우/인증 실패/건물 정보 누락 시 오류를 표시하고 임의 면적을 사용하지 않음

## 2. API 인증키 준비

1. https://www.vworld.kr/ 접속 → 회원가입 → 오픈API → 인증키 발급(활용신청).
2. 서버용 키: 지오코더, 2D 데이터(연속지적도), 국가중점데이터(토지임야정보, GIS건물통합 WFS)를 사용할 수 있는지 확인. 필요한 운영 승인 절차도 확인합니다.
3. 지도용 키: WMTS/배경지도 사용 권한을 갖는 웹용 키를 발급하고 실제 Vercel 도메인 및 로컬 테스트 URL을 허용합니다. 서버 키와 별도 사용 권장. 지도용 키는 브라우저에 표시되므로 도메인 제한이 중요합니다.
4. 키별 사용 가능 API, 도메인 등록 방식 및 승인 조건은 브이월드 신청 화면에서 확인합니다. 유효한 키 없이 실제 조회는 불가능합니다.

공식 참고: https://www.data.go.kr/data/15123970/openapi.do (GIS건물통합정보), https://www.data.go.kr/data/15123884/openapi.do (토지임야정보), https://www.vworld.kr/ (지도·지오코더·2D 데이터).

## 3. 로컬 실행 (Windows PowerShell)

기존 프로젝트를 먼저 백업하고, 압축을 풀어 해당 프로젝트 폴더에서 실행합니다. 원본과 동일한 pnpm lockfile을 유지했으며 새로운 npm 라이브러리를 추가하지 않았습니다. node_modules는 OS별 바이너리가 포함되므로 배포 패키지에서 제외했습니다.

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env.local
notepad .env.local
```

`.env.local`에 발급된 키 입력:

```env
VWORLD_API_KEY=서버용_인증키
VWORLD_DOMAIN=
VITE_VWORLD_MAP_KEY=웹지도용_인증키
```

서버용 키에 도메인 제한을 설정한 경우 `VWORLD_DOMAIN`에 키와 일치하는 등록 URL을 넣습니다. 제한 없는 서버용 키라면 비워 둡니다. 지도용 키는 `http://localhost:5173` 등 로컬 URL을 허용해야 합니다. 환경변수 변경 후에는 개발 서버를 재시작합니다.

```powershell
pnpm dev
```

브라우저에서 터미널에 출력된 URL을 열면 됩니다. Vite 개발 서버에도 동일한 API 처리기를 등록했으므로 별도 서버 실행은 필요 없습니다.

```powershell
pnpm test
pnpm build
```

## 4. Vercel 반영

- 기존 Git 저장소에 적용할 경우 새 테스트 브랜치를 만들어 다음 파일을 복사/추가합니다: `src/components/InputView.jsx`, `src/components/SiteAreaLookup.jsx`, `src/utils/siteArea.js`, `api/site-area.js`, `server/siteArea.js`, `vite.config.js`, `vercel.json`, `.env.example`, `tests/site-area.test.js`, `package.json`, `.gitignore`, 이 문서. 이미 운영 저장소에 별도 API·접근 제어·환경변수·vercel.json 설정이 있다면 해당 기존 파일을 덮어쓰지 말고 병합하세요. 업로드된 로컬 원본에는 접근제어 파일이 없었습니다.
- Vercel 프로젝트 Settings → Environment Variables에 `VWORLD_API_KEY`, `VITE_VWORLD_MAP_KEY`, 필요한 경우 `VWORLD_DOMAIN` 등록. 서버 키는 절대 `VITE_` 접두어를 붙이지 않습니다.
- 테스트 브랜치 Preview 환경에 환경변수를 설정하고 배포해 조회 후, Production에도 등록하고 재배포합니다. Vite 공개 환경변수는 빌드 시 반영됩니다.
- 지도 타일은 브라우저가 브이월드에서 직접 불러오며 Vercel API는 JSON 공간정보만 전달합니다. 지도 조회 패널을 열거나 주소를 입력하는 것만으로 외부 API를 호출하지 않고 조회 버튼을 눌렀을 때 호출합니다. 영구 캐시/저장 기능은 포함하지 않았습니다.
- 기관 업무용으로 사용 시 Vercel Hobby 및 브이월드의 실제 사용조건을 별도로 확인하세요.

## 5. 면적 환산 및 지역 매핑

초기 검토용 가정값: 일반부지 13.2㎡/kW, 건축물 6.6㎡/kW. 면적 ÷ 필요 면적의 소수점 이하를 버립니다. 예: 1,320㎡ 토지 → 100kW, 660㎡ 건물 → 100kW. 화면에서 환산 기준을 수정할 수 있으며, 기본값은 `src/utils/siteArea.js`의 `AREA_PER_KW`에서 변경합니다. 정확한 설비 용량/설계 또는 인허가 판단값은 아닙니다.

기존 9개 지역의 일조량을 유지합니다. 서울·경기·인천 → 서울경기, 대전·세종 → 충청남도, 대구 → 경상북도, 부산·울산 → 경상남도, 광주 및 전남광주통합특별시 → 전라남도. 광역시의 일조량은 인접 도 단위 기존 수치로 매핑한 가정입니다. 분류: 토지→일반부지(REC 기본 1.2), 건물→건축물(REC 기본 1.5); 기존 수치 유지, 실제 REC 인정 여부는 별도 검토 필요.

## 6. 확인 및 제한사항

- Node 단위 테스트로 면적 환산, 지역 매핑, 모의 지적대장·건물 응답, 중복 도형 제거, 건물 API 실패 처리, 키 미설정을 검증했습니다. JSX 문법 검사도 수행했습니다.
- 제공된 파일에 실제 인증키가 없으므로 브이월드 실주소 조회 및 배포 동작은 검증하지 못했습니다. 실행 환경에서 전체 Vite 빌드 및 UI 실화면 확인도 별도로 필요합니다. API 응답 필드나 승인 조건이 달라질 경우 `server/siteArea.js`에서 해당 호출부를 수정해야 할 수 있습니다.
- 주소 좌표가 속한 단일 필지를 기준으로 조회합니다. 여러 필지에 걸친 부지는 각각 조회해야 합니다. 건물 조회는 필지 PNU 기준이며 건물 데이터 미등록·갱신 지연 또는 인접 필지에 걸친 건물 때문에 실제와 다를 수 있습니다. 건물 면적은 수평투영면적의 합계이며 경사지붕, 장애물, 이격거리, 음영, 구조하중은 반영하지 않습니다.
- 권장 실주소 테스트: 일반 나대지, 단독 건물 필지, 여러 건물 필지, 도로명과 지번의 동일 대상 조회, 50kW 미만 및 1,000kW 초과 환산값, 잘못된 인증키/주소, 토글 닫기 후 기존 계산 유지, 지도 타일 도메인 제한.
